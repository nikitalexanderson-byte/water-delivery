# Android экспедитора

Минимальная версия Android 8.0 (API 26). Проект использует Kotlin, Jetpack Compose Material 3 и Gradle Wrapper. Для сборки нужны JDK 21 или совместимый JBR из Android Studio, Android SDK Platform 36.1 и Build Tools. Сборка CI находится в `.github/workflows/android.yml`.

**Windows.** Из корня репозитория выполните:

```powershell
.\apps\android\build-local.ps1
```

Скрипт собирает рабочие исходники через Gradle во временном каталоге и сохраняет проверенную сборку в `.local/apk/farvater-driver-debug.apk`. Такой запуск подходит для синхронизируемых папок, в которых Windows добавляет `desktop.ini` в каталоги Android-ресурсов.

**Linux или macOS.** Из каталога `apps/android` выполните:

```sh
bash gradlew testDebugUnitTest assembleDebug
```

APK будет в `app/build/outputs/apk/debug/app-debug.apk`. GitHub Actions выполняет те же задачи и сохраняет APK в артефактах запуска.

**Подключение к backend.** По умолчанию debug-сборка использует `http://10.0.2.2:8080` — адрес компьютера из стандартного Android Emulator. При другом порте или способе подключения задайте `ANDROID_API_URL` перед сборкой. Например, на личном тестовом телефоне с USB-пробросом локального порта используйте `http://127.0.0.1:8080`. Приложение ставится через Android Studio или системный установщик APK. Для входа используйте `driver1@farvater.test` либо `driver2@farvater.test` и пароль из `DEMO_PASSWORD`.

**Проверка рейса.** Подтвердите выход в «Моей смене». После распределения диспетчером нажмите «Обновить смену». На завтра маршрут открывается с 18:00 по времени базы. Фактический выезд и загрузку водитель вводит при отправлении. При доставке подтвердите факт оплаты и пустую тару, либо укажите причину неудачи. При наличии свободной воды доступна допродажа. После возврата каждого рейса сдайте полную и пустую тару, наличные и подтверждённый безнал. В результате видны ожидаемые и фактические значения, суммы расхождений и вознаграждение.

**Бренды воды.** Каждая позиция заказа показывает бренд, число бутылей и цену. На погрузке проверьте количество по каждому бренду и при необходимости добавьте запас из каталога. Подтверждение доставки относится ко всем строкам заказа. При допродаже выберите бренд из свободного остатка рейса. При сдаче введите пересчитанные количества отдельно, включая нули. Отчёт покажет излишек или недостачу по каждому бренду даже при совпадении общего числа бутылей.

**Связь и напоминания.** Последний открытый день и токен хранятся на устройстве в зашифрованном виде. При потере ответа на запись приложение хранит её тело и UUID до восстановления связи. Кнопка повтора отправляет сохранённую операцию. Открытый экран обновляет день раз в минуту. При получении опубликованного маршрута приложение ставит системные напоминания за 90 минут до ETA и пересчитывает их при следующем обновлении. Если до ETA осталось меньше 90 минут, сигнал запрашивается при синхронизации. Для Android 13+ пользователь включает разрешение на экране смены. Экономия батареи может сдвинуть сигнал. После перезагрузки устройства приложение нужно открыть для восстановления расписания. Уведомление об изменении маршрута появляется после синхронизации.

**Проверка на устройстве, 23 ноября 2026.** На Samsung Galaxy A56 5G (Android 17, API 37) через USB проверены вход, подтверждение смены, получение маршрута, фактическая загрузка двух брендов, доставка, возврат и сдача смены. Для 3 доставленных бутылей и 1 новой тары Android и кабинет диспетчера показали 1 350 ₽ наличными, 1 полную бутыль к возврату и 2 пустых. Android зарегистрировал уведомления об изменении маршрута и звонке, когда до ETA оставалось менее 90 минут.

При подтверждении этой доставки тестовый ретранслятор оборвал ответ после успешной записи сервером. После остановки и повторного открытия приложения без сети сохранилась кнопка повтора. После восстановления связи рейс завершился с одной доставкой, одним списанием и одной оплатой. Полный голосовой проход с TalkBack и точность срабатывания напоминания при длительном сне телефона остаются отдельными проверками.

**Повторное подключение по USB.** Для debug APK, собранного с `ANDROID_API_URL=http://127.0.0.1:18019`, включите локальный API на компьютере и выполните в PowerShell. Для телефона, подключённого одновременно с эмуляторами, укажите его идентификатор из первой команды.

```powershell
$adb = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe'
& $adb devices -l
$deviceId = Read-Host 'ID телефона из списка ADB'
& $adb -s $deviceId reverse tcp:18019 tcp:8080
```

Для изолированного прогона можно направить тот же порт телефона на отдельный локальный API с тестовой базой. После проверки выйдите из тестового кабинета перед переключением на обычный стенд.
