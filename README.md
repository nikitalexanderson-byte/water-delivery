# ФАРВАТЕР

Локальный MVP диспетчеризации доставки воды в бутылях 19 л. Оператор принимает заказ в браузере, экспедитор подтверждает смену в Android, диспетчер распределяет точки. После возвращения система сверяет воду, тару, наличные и безнал и формирует дневной отчёт.

## Быстрый старт на Windows

Нужны Git и Node.js 22.13+ (также проверено на 24). Из корня репозитория:

```powershell
Copy-Item .env.example .env
npm ci
npm run build
npm start
```

Копируйте шаблон только при первом запуске. Откройте [панель](http://127.0.0.1:8080). API и собранная панель работают на одном порту. Остановка в терминале — Ctrl+C. При разработке веба во втором терминале запустите `npm run dev`. Vite проксирует запросы к API. При другом порте укажите `API_PORT`, для другого адреса API — `API_ORIGIN`.

### Кабинеты стенда

| Кабинет | Email | Доступ |
| --- | --- | --- |
| Оператор | operator@farvater.test | Справочник клиентов, история, приём, повтор и редактирование заказов, проверка адреса, отмена и перенос |
| Диспетчер | dispatcher@farvater.test | Очередь, машины, смены, маршруты и сверка |
| Экспедиторы | driver1@farvater.test, driver2@farvater.test | Свои смены, опубликованные рейсы, доставки, сдача |
| Руководитель | manager@farvater.test | Просмотр дня, отчёты и подтверждение проверки расхождений |

Пароль демопрофилей задаёт `DEMO_PASSWORD` при первом создании базы. Значение в шаблоне — `local-farvater-19`. В кабинете пароль можно изменить. Повторный запуск сохраняет данные и пароли. Создание синтетики включается через `SEED_DEMO=true`. Реальный тариф воды задаётся при оформлении заказа; исходные 350 ₽ — пример. Цена новой тары 250 ₽.

### Наименования воды и парк

В разделе «Каталог» диспетчер или руководитель создаёт наименования воды 19 л, задаёт цены и снимает позиции с продажи. На стенде две учебные позиции. Оператор может добавить несколько разных брендов в один заказ. Наименование и цена каждой строки сохраняются на дату оформления. Архивирование позиции сохраняет историю и возможность исполнить уже принятый заказ.

Загрузка, свободные остатки, допродажа и сдача смены учитывают каждый бренд отдельно. Например, лишняя бутыль одного бренда и недостающая бутыль другого дают два расхождения даже при совпадении общего количества. Состав отметки доставки проводится одной транзакцией.

Автомобили и сотрудники добавляются как записи в БД. Число записей свободное. Ограничение двух рейсов относится к одной смене. Автотест проверяет 100 заказов для 10 и 1000 водителей с машинами, включая назначение на последнего водителя в списке. Перед эксплуатацией большого парка предстоит отдельно измерить нагрузку на API, БД и обновление диспетчерского экрана.

### Как провести учебную доставку

1. В день первого запуска стенд создаёт две смены на сегодня и две на завтра. Выберите дату в панели. Для другой даты диспетчер может создать смену в «Маршруты → Смены и машины».
2. В Android войдите как экспедитор и подтвердите выход. Первый экспедитор работает до 18:00, второй — до 22:00. Каждый может подтвердить только свою смену.
3. В журнале нажмите «Новый заказ». Найдите клиента по имени, телефону или адресу либо введите нового. Укажите проверенный адрес, окно, бренды, количество и новую тару. Для безнала укажите компанию. В разделе «Клиенты» можно открыть историю и повторить прежний заказ с проверкой даты, окна и состава.
4. Войдите как диспетчер, откройте маршруты и запустите распределение. Для вечера выбирайте смену, в которую помещается и обратный путь. Машины с неизвестной полной высотой не проходят проверку ограниченного въезда. Неподходящие заказы остаются в очереди с причиной.
5. В Android обновите маршрут. Завтрашние точки доступны с 18:00 по времени базы. В день смены укажите фактическое время выезда и погрузку. Подтвердите доставку, фактическую пустую тару и оплату. Отдельным действием можно продать свободную воду или зарегистрировать недоставку.
6. Отметьте возврат на базу после всех точек. После последнего рейса введите фактически пересчитанные деньги и тару. Диспетчер и руководитель увидят результат, расхождения и CSV в «Отчёте за день».

В позднее время используйте планирование на завтра. Для воспроизводимого прохождения всей смены в любой час дня тесты управляют часами API.

### Исправление заказа

До выезда откройте заказ из журнала и выберите редактирование. В той же форме можно уточнить телефон для этой доставки, подъезд, офис, домофон, инструкции по въезду или корзину. Заказ сохраняет номер. Если он уже был в плане, после изменений появится сообщение о возврате в очередь. Диспетчер сможет распределить его заново. Порядок и ETA оставшихся точек исходного рейса обновятся автоматически.

### Карта рейсов

После локального запуска можно открыть [рабочую карту](http://127.0.0.1:8080/?view=atlas) или [два учебных рейса на карте](http://127.0.0.1:8080/?view=atlas&example=1). После входа откроется выбранный вид.

В боковом меню веб-панели откройте «Карта рейсов». Выберите рейс или оставьте общий обзор. Кнопка остановки в списке выбирает её на карте, нажатие на маркер открывает сведения о точке. Для просмотра интерфейса на пустой базе доступен отдельный учебный пример с районами Москвы. Его остановки не записываются в журнал.

Уличная карта открывается и в день без назначенных рейсов. Кнопка «Моё местоположение» запрашивает разрешение и показывает текущую точку устройства. В браузере для этого нужен localhost или HTTPS. Такой просмотр сохраняет позицию только на устройстве. На форме заказа отдельно укажите точку доставки на карте либо введите широту и долготу. Координаты производства задайте парой `BASE_LAT` и `BASE_LON`, адрес — через `BASE_ADDRESS`.

Для поиска места введите город, улицу, дом или название и запустите поиск кнопкой. Сверьте населённый пункт и точку на карте перед выбором. Публичный Photon использует данные OpenStreetMap и работает по доступности сервиса. Поиск вызывается при отправке запроса. При `GEOCODER_ENABLED=false` можно по-прежнему поставить точку вручную. [Photon](https://github.com/komoot/photon)

По умолчанию при наличии сети клиент загружает стандартные растровые тайлы OpenStreetMap с `tile.openstreetmap.org`. Для автономной работы задайте `MAP_TILES_ENABLED=false`. Если в старом `.env` уже стоит `false`, для уличной карты установите `true` и перезапустите локальный API. В Compose примените изменение через `docker compose up -d api`.

Leaflet 1.9.4 и обзорные векторные слои Московского региона входят в веб-сборку и APK. Они позволяют видеть общий контекст без тайлов. Схема показывает последовательность остановок даже при неполных координатах. В географическом режиме линии соединяют остановки по порядку. Для автомобильного пути откройте ссылку на Яндекс Карты. ETA в каждом режиме рассчитывает учебный провайдер. [Условия использования стандартных тайлов OSM](https://operations.osmfoundation.org/policies/tiles/)

## Локальный PostgreSQL и Docker

Из корня с заполненным `.env`:

```sh
docker compose up --build -d
docker compose ps
docker compose logs api
docker compose stop
```

Остановите другой экземпляр на том же порту или измените `API_PORT`. Compose запускает PostgreSQL 17 с именованным томом и API с вебом. Наружу публикуется порт панели на loopback. Проверка готовности — `GET /health/ready`. Нумерованные SQL-миграции выполняются под блокировкой до начала обслуживания запросов.

Без Docker запускается PGlite с теми же SQL-миграциями. В Windows файлы базы по умолчанию хранятся в `%LOCALAPPDATA%/Farvater/<идентификатор каталога>/postgres`, вне синхронизируемой папки. Доступ к этому каталогу получает один процесс. Для собственного пути задайте `LOCAL_DB_DIR`. Чтобы подключить обычный PostgreSQL, укажите `DATABASE_URL` либо стандартные `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`. Эти профили используют независимые базы. День, адрес базы и необязательная пара координат задаются через `BUSINESS_TZ`, `BASE_ADDRESS`, `BASE_LAT`, `BASE_LON`.

## Android и автоматические проверки

```powershell
.\apps\android\build-local.ps1
npm test
npm run build
npx playwright install chromium
npm run test:web
```

Windows-скрипт сохраняет APK в `.local/apk/farvater-driver-debug.apk`. По умолчанию он обращается к `http://10.0.2.2:8080` из стандартного эмулятора. Для другого адреса задайте `ANDROID_API_URL` перед сборкой. Подробности приведены в [инструкции Android](apps/android/README.md).

Для уже установленного Chrome можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Браузерные тесты запускают свой API и БД в памяти. Для проверки API на серверном PostgreSQL укажите `TEST_DATABASE_URL` **только для новой пустой тестовой БД**. Интеграционные тесты создают и изменяют в ней данные. CI поднимает одноразовый PostgreSQL, собирает веб, запускает браузерные проверки и в отдельной задаче собирает debug APK.

[Правила и UX](docs/design.md) · [Контракт API](docs/api.md) · [Подготовка будущего сервера](docs/server.md)

Этап использует учебные адреса и тестовый провайдер времени пути. Рабочий стенд получает адрес и координаты производства в Сальково из своего окружения. При переносе на другой компьютер или VPS перенесите `BASE_ADDRESS`, `BASE_LAT` и `BASE_LON` из действующего .env в конфигурацию нового сервера. Ближайшие работы перед пилотом — на реальных машинах проверить полную высоту и запас массы, согласовать тариф воды и учёт нескольких заказов по одному адресу, проверить устройства экспедиторов, качество адресного поиска и точность времени обслуживания. Более широкая офлайн-синхронизация, пробки, Google Sheets, частичные доставки и финансовые корректировки относятся к следующим этапам.
